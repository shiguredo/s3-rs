# XML パースの DoS 耐性確認

Created: 2026-04-04
Completed: 2026-04-05
Model: Opus 4.6

## 概要

`src/xml.rs` で巨大・深いネストの XML に対する防御が xml-rs クレートの安全性に完全に依存している。

## 懸念

- 攻撃者が巨大な XML レスポンスを返すプロキシを経由した場合、メモリ枯渇の可能性
- 深くネストされた XML によるスタックオーバーフローの可能性

## 調査結果

- xml-rs 1.2 には入力サイズやネスト深さの制限設定がない
- xml-rs はイテレータベースの SAX パーサーであり、DOM ツリーを構築しないため、深いネストによるスタックオーバーフローのリスクは低い
- メモリ枯渇は巨大ボディをそのまま文字列化する際に発生しうる

## 解決方法

レスポンスボディの XML パース前にサイズ上限チェック (10MB) を追加した。

- `xml_body_text()` ヘルパー関数を `api/mod.rs` に追加（サイズチェック + UTF-8 変換を一体化）
- 全 XML パースを行う `parse_response` 関数で `xml_body_text()` を使用するよう統一
- `check_body_error()` にもサイズガードを追加
- S3 の XML レスポンスは通常数百 KB 以内のため、10MB は十分な余裕を持った防御ライン
